# 开发与发布

## 分支与版本

`main` 保存经验证的发布版本；`dev` 接收后续开发。开发分支使用开发版本号，发布分支使用正式版本号，版本来源是 `netpilot_lib/__init__.py`。正式发布使用对应的 `vX.Y.Z` 标签。

`AGENTS.md`、`CLAUDE.md`、`SHA256SUMS.txt` 和 `handoff.md` 仅在 `dev` 跟踪。`main` 保留源码、教程、示例、测试和 CI，不包含这四个开发专用文件。

```bash
git fetch origin
git switch dev
# 修改代码及对应教程，然后运行离线检查
git add <已检查的文件>
git commit -m "描述具体行为变化"
git push origin dev
```

发布时先在 `dev` 完成验证并更新校验清单，再从 `main` 准备发布分支（以下以 0.1.2 为例）：

```bash
git switch main
git switch -c release/0.1.2
git merge --no-ff --no-commit dev
git rm --ignore-unmatch -- AGENTS.md CLAUDE.md SHA256SUMS.txt handoff.md
# 更新正式版本号、README 和 CHANGELOG，运行下述离线检查后提交
```

若合并在开发专用文件上出现修改/删除冲突，仍按上述 `git rm` 移除它们；其他冲突逐项核对后解决。检查发布差异，确认四个开发专用文件已移除、`main` 的 README 不含“使用边界”章节、文档没有失效相对链接，再通过评审合入 `main` 并标记版本。同步 `main` 的公共变更回 `dev` 时，保留开发专用文件并重算校验清单。不要 force-push 发布历史，也不要移动已有发布标签。分支不自动配置 GitHub 保护规则，仓库管理员可另外设置审核要求。

## 模块与安全约束

| 模块 | 责任 |
|---|---|
| `network_setup.sh` | 系统 Python、依赖检查、明确确认后的安装和 sudo 启动 |
| `netpilot.py` | 菜单、连接管理、导入导出、系统备份、事务确认 |
| `netpilot_lib/common.py` | 输入校验、参数列表子进程、私有文件、连通性测试 |
| `netpilot_lib/network.py` | 网卡、角色向导、计划校验、诊断 |
| `netpilot_lib/nm.py` | D-Bus、秘密、检查点、内存连接和持久保存 |
| `netpilot_lib/routes.py` / `route_guard.py` | 精确临时路由归属和独立 systemd 恢复 |
| `netpilot_lib/proxy.py` | 用户代理文件、Bash/APT 开关、旧代理备份清理 |
| `netpilot_lib/github_ssh.py` | 当前用户密钥、SSH 配置备份、公钥展示和确认后的 GitHub 验证 |

开发遵循 [dev 分支的 AGENTS.md](https://github.com/AllenW-Hiter/WBS-Netpilot/blob/dev/AGENTS.md)：不对开发机网卡执行写操作，不运行真实 APT 安装，不清空防火墙；命令参数使用列表，密码不进入 argv、日志和计划；新连接先检查点及内存试运行，确认后保存；临时路由只操作精确归属记录。原用户配置、Netplan renderer、unmanaged 接口和全局策略不自动接管。

## 离线验证

```bash
/usr/bin/python3 -m unittest discover -s tests -v
/usr/bin/python3 -m compileall -q netpilot.py netpilot_lib tests
bash -n network_setup.sh
./network_setup.sh --check
./network_setup.sh --dry-run --plan examples/client_static.json
./network_setup.sh --demo
```

当前共 **227 项离线单元/模拟测试**，其中 GitHub SSH 向导新增 34 项测试。本次在 Ubuntu 22.04.5、系统 Python 3.10.12 通过全部测试、编译、Bash 语法、只读检查及计划预览。

套件涵盖输入、角色向导、D-Bus 模拟事务、失败恢复、连接命名、代理开关及 GitHub SSH。Git/SSH 文件测试使用临时用户目录；OpenSSH 离线测试生成临时密钥、通过临时终端验证口令提示，并以 `ssh -G` 检查配置，不连接网络。APT、sudo、网卡、路由和 GitHub 认证使用模拟。模拟结果不等于硬件兼容或真实网络验收，Ubuntu 22.04/24.04 目标设备仍需验证无线、DHCP/NAT、SSH 恢复和代理端到端路径；GitHub 账户授权及在线 SSH 验证需使用者完成。

GitHub Actions 对 `main`、`dev` 推送及指向这些分支的拉取请求执行离线检查，不安装网络管理器或修改网卡。SHA256 清单检查仅对 `dev` 推送及指向 `dev` 的拉取请求执行；`main` 和发布标签不依赖清单文件。运行结果以实际工作流为准。

## 发布检查

只提交源码、教程、无秘密示例和测试。检查 `.gitignore` 已排除真实连接文件、代理认证、备份、诊断导出、编辑器配置和 Python 缓存。

```bash
git status --short
git diff --cached --check
```

在 `dev` 新增/修改受跟踪文件后重算 `SHA256SUMS.txt`，清单本身不参与自身哈希，并运行 `sha256sum -c SHA256SUMS.txt`。发布分支和 `main` 不生成或跟踪该文件。发布前运行全部规定检查，记录实机测试的系统、网卡、驱动和实际结果；禁止把离线通过改写为“保证不断网”。

底层行为参考：[NetworkManager 检查点](https://www.networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.html)、[APT 加载规则](https://manpages.ubuntu.com/manpages/jammy/man5/apt.conf.5.html)、[APT 代理](https://manpages.ubuntu.com/manpages/jammy/man1/apt-transport-http.1.html)、[Git 配置](https://git-scm.com/docs/git-config)。
