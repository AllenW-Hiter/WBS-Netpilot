# 主机与从机配置：通过主机共享上网

## 目标与示例

主机已经能访问互联网，通过另一块网卡把网络共享给从机。本篇以“主机 Wi-Fi 上网、网线连接从机”为例，两端都使用 Ubuntu/Debian 和 NetworkManager。

```mermaid
flowchart LR
    C["从机：有线网卡"] --> H["主机：面向从机的有线网卡"]
    H --> U["主机已经连接的 Wi-Fi"]
    U --> I["互联网"]
```

| 项目 | 本例配置 |
|---|---|
| 主从机之间的网段 | `192.168.50.0/24` |
| 主机下行地址 | `192.168.50.20/24` |
| 从机固定地址 | `192.168.50.30/24` |
| 从机网关和 DNS | `192.168.50.20` |
| 自定义 DHCP 池（支持时） | `192.168.50.100`～`192.168.50.199` |

这些地址是示例，需在两端手动填写。若与已有 Wi-Fi、VPN、Docker 或其他网络重叠，换用一个未占用的网段，并同步修改两端。共享出口跟随主机的系统路由。

## 1. 两端准备

两台机器均准备好 NetPilot 项目，在项目目录执行：

```bash
./network_setup.sh --check
./network_setup.sh --status
```

根据状态识别实际网卡名称：主机的上行接口，以及两端连接网线的接口。用网线或专用交换机连接主从机，主机的上行和下行使用不同物理网卡。

网络写操作会按需请求 sudo，安装缺失依赖前会询问。若接口显示 unmanaged，先确认现有网络管理方式；工具不会自动接管。修改承载当前 SSH 的接口可能断开连接，应准备本机终端或其他恢复通道。

## 2. 在主机建立上行

主机已经正常联网时可跳过配置。需要连接 Wi-Fi 时运行：

```bash
./network_setup.sh uplink
```

等同主菜单 **1. 网络设置与检测 → 配置本机上行**。选择 Wi-Fi 网卡，地址方式选 DHCP，按提示填写 SSID、安全方式和密码。试运行正常后，输入完整大写 `KEEP` 保存。

在主机验证上行：

```bash
ip -4 route get 1.1.1.1
curl -q --proxy '' --noproxy '*' -I --max-time 15 https://example.com
```

这里显式绕过应用代理，用来验证主机的系统联网路径。网站可换成当前网络允许访问的 HTTPS 站点。

## 3. 在主机启用共享

在主机运行：

```bash
./network_setup.sh host
```

等同 **1. 网络设置与检测 → 配置主机/共享网关**，按下表选择：

| 向导项目 | 填写或选择 |
|---|---|
| 主机模式 | Wi-Fi 上行 → 有线共享 |
| 已连接的上行接口 | 主机当前联网的 Wi-Fi 网卡 |
| 面向从机的下行接口 | 接往从机的有线网卡 |
| 有线连接名称 | 自行填写，例如 `主从机共享` |
| 网段 | `192.168.50.0/24` |
| 主机地址末段 | `20` |
| 从机地址末段 | `30` |
| 开机自动启用 | 按需选择 |

主机向导中的从机地址用于配置提示，不会替从机设置网卡。若程序提示实际出口与所选上行不同，先核对系统路由和 VPN；确认接受当前系统出口后再按提示输入 `FOLLOW`。

DHCP 地址池按现场能力选择：

- 支持自定义池时，使用 `.100`～`.199`，避开主机 `.20` 和固定从机 `.30`。
- 不支持自定义池时，如果链路只连接这一台静态从机，选择“专用直连、仅一台静态从机”，不要混接 DHCP 客户端。
- 需要接入多台设备且无法安排安全的固定地址时，选择“下游全部使用 DHCP”，下一步从机也选 DHCP；从机实际地址由主机分配，不保证是 `.30`。

核对计划并同意试运行。在另一终端确认主机有线地址和上行仍正常，再返回输入 `KEEP`。默认确认窗口为 180 秒；输入其他内容会请求撤销，未确认会超时恢复。程序无法创建原生检查点时会停止。

## 4. 在从机配置地址与网关

在从机运行：

```bash
./network_setup.sh client
```

等同 **1. 网络设置与检测 → 配置从机/静态 IP**。使用本例固定地址时：

| 向导项目 | 填写或选择 |
|---|---|
| 接口 | 从机连接主机的有线网卡 |
| 从机联网策略 | 固定 IP，持久默认网关 |
| 有线连接名称 | 自行填写，例如 `通过主机上网` |
| 网段、主机末段、从机末段 | `192.168.50.0/24`、`20`、`30` |
| DNS | `192.168.50.20` |
| 开机自动启用 | 按需选择 |

程序根据主机地址填写默认网关。若上一步选择了“下游全部使用 DHCP”，此处改选 **DHCP 自动获取**，无需手动填写固定 IP、网关和 DNS。

同意试运行后，保留确认终端，在另一终端执行下一节的验证；正常后再输入 `KEEP`。

## 5. 在从机验证

```bash
ip -4 address
ip -4 route get 1.1.1.1
ping -c 3 192.168.50.20
getent hosts example.com
curl -q --proxy '' --noproxy '*' -I --max-time 15 https://example.com
```

| 检查项 | 预期结果 |
|---|---|
| 地址 | 固定模式下为 `192.168.50.30/24`；DHCP 模式下为分配的同网段地址 |
| 到公网的路由 | 经主机 `192.168.50.20`，接口为接往主机的网卡 |
| 主机可达性 | 能访问主机下行地址；禁用 ICMP 的环境需用已开放的服务另行验证 |
| DNS | 能解析测试域名 |
| HTTPS | 能完成请求；再验证自己实际需要访问的站点 |

已有其他默认路由时，实际流量可能走其他接口，应以路由查询结果为准。仅看到连接激活或能 ping 主机，不能证明从机已经通过主机访问互联网。

## 按需联网与停止共享

希望该从机连接不持久保存默认网关时，在从机配置中选择 **固定 IP，按需临时网关**，需要通过主机上网时执行：

```bash
# 从机：添加临时网关，填写主机地址，并在验证后输入 KEEP。
./network_setup.sh route-on
# 从机：撤销本工具登记的临时网关，同样按提示确认。
./network_setup.sh route-off
```

主机需要停止共享并保留原管理地址时执行：

```bash
./network_setup.sh shared-stop
```

这些操作各有试运行和确认流程。临时网关只管理工具登记的精确路由，不会清空其他路由。

## 常见问题

| 现象 | 处理方向 |
|---|---|
| 找不到目标接口 | 检查网线、物理网卡及 NetworkManager 托管状态 |
| 从机可访问主机，无法访问互联网 | 确认主机选择了共享模式、上行可用，以及从机实际默认路由 |
| IP 可达，域名无法解析 | 检查从机 DNS 和主机共享 DNS 服务 |
| 主机能上网，从机请求仍失败 | 查看主机 Docker、UFW、nftables 或 VPN 的转发策略，不要清空防火墙 |
| 从机也需要借用主机的应用代理 | 见[代理教程中的网线来源](02_远程服务器SSH代理.md#同一局域网内使用网线主机代理) |

需要进一步排查时，在对应机器运行 `./network_setup.sh --diagnose`。导出报告可能包含 IP、SSID 和路由，分享前检查。以上是操作步骤与预期结果，实际设备的联网效果需现场验证。
