# 应用代理

使用本机可达的现有 HTTP、HTTPS 或 SOCKS5h 代理服务。代理服务器须监听正确地址和端口，并允许该客户端访问。程序不修改代理软件、防火墙或系统路由。

```bash
./network_setup.sh proxy
```

| 编号 | 操作 |
|---|---|
| 1 | 配置/更新 |
| 2 | 测试当前代理 |
| 3 | 安装/更新终端代理开关函数 |
| 4 | 清理旧 APT / Git 代理配置 |
| 5 | 移除本用户代理配置 |

## 配置

选择协议并填写服务器地址、端口、可选认证和绕过列表。例如 HTTP 代理 `192.168.1.20:10808`。端口须取自代理软件实际配置，不能使用控制 API 端口。

保存时先私有备份并清理旧 APT / 当前用户全局 Git 代理项，再在 `~/.bashrc` 定义 `netpilot_proxy_on/off`。代理认证保存在 `~/.config/netpilot/` 的 `0600` 文件，不写入 `.bashrc`。选择测试成功表示程序通过所填代理完成了一次 HTTPS 请求，不表示父终端已启用代理。

HTTP 可通过 CONNECT 访问 HTTPS 网站；“HTTPS 代理”指与代理服务器之间使用 TLS；SOCKS5h 由代理端解析目标域名。

## 开启与关闭

退出工具后，在 Bash 终端执行：

```bash
source ~/.bashrc
netpilot_proxy_on
sudo apt update
git ls-remote https://github.com/git/git.git HEAD
curl -I https://example.com

netpilot_proxy_off
```

开启先通过 sudo 写入并验证系统 APT 配置，再设置本终端环境变量；失败时终端变量保持不变。关闭先移除本工具 APT 文件并验证，再恢复本终端启用前的变量；没有原变量时取消设置。

APT 开关影响系统 APT。Git HTTPS、curl 等影响当前终端及以后从它启动的程序。新终端不自动设置代理环境变量，APT 保持当前系统状态。Git SSH、系统服务、其他终端和已经启动的进程需要分别处理；该功能不代理所有流量，ping 的 ICMP 也不使用 HTTP 代理。

单命令模式只设置子进程环境，不操作系统 APT 开关：

```bash
./network_setup.sh proxy-run -- curl -I https://example.com
```

## 清理旧配置

已有私有配置时，菜单 **4 → 3** 可清理旧规则并升级函数，无需重填。也可显式运行：

```bash
sudo ./network_setup.sh proxy-cleanup
```

APT 清理删除生效配置中的完整单行代理指令，保留其他设置；只含代理和注释的文件会移除，例如旧 `99proxy`。嵌套或无法确定范围的语法、符号链接会停止，需人工整理。Git 清理只涉及用户主目录内的全局及 include 文件，不遍历仓库或改系统 Git 配置；姓名、邮箱等保留。

APT 备份位于 `/var/lib/netpilot/backups/proxy/`；Git 备份位于 `~/.config/netpilot/legacy-proxy-*`。历史私有备份继续保留。代理函数内部的 APT 文件是 `/etc/apt/apt.conf.d/99-netpilot-proxy`，关闭后移除。

APT 仍连接旧端口时，检查 `sudo apt-config dump` 和 `/etc/apt` 中代理来源。Git 仓库级、系统级或命令行代理设置可能覆盖环境变量。分享诊断内容前去掉认证信息，更多步骤见[故障处理](07_诊断与故障处理.md)。
