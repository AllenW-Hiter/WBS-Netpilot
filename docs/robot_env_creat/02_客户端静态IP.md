# 客户端设置静态 IP

## 任务

将机器人连接主机的有线网卡设为固定地址 `192.168.1.30/24`，连接名称为 `机器人控制网络`。使用主机的 `192.168.1.20` 作为默认网关和 DNS，让机器人通过主机共享网络，并保持固定的控制地址。

主机应已按[第一篇教程](01_主机WiFi上行与有线共享.md)启用或正在试运行共享。两端网线已连接，主机 DHCP 池避开 `.30`，或使用专用单台静态机器人链路。确认没有其他设备使用 `.30`；两台设备各自填写相同连接名称不会冲突。

## 通过 NetPilot 执行

### 1. 进入客户端向导

在机器人的项目目录运行：

```bash
./network_setup.sh --status
./network_setup.sh client
```

这相当于主菜单 **3. 配置从机／客户端**。选中接往主机的实际有线网卡，按下表填写：

| 软件提示 | 选择或输入 |
|---|---|
| 从机联网策略 | **2. 固定 IP，持久默认网关** |
| 连接名称 | `机器人控制网络` |
| 网段 | `192.168.1.0/24`，也可填 `192.168.1` |
| 主机地址末段 | `20` |
| 从机地址末段 | `30` |
| DNS | `192.168.1.20` |
| 成功后开机自动启用 | 按使用需要选择，通常填 `y` |

软件根据主机地址生成默认网关 `192.168.1.20`。检查计划中的机器人地址为 `192.168.1.30/24`，不是主机的 `.20`，然后按提示执行地址占用探测并确认试运行。

通过当前网卡的 SSH 会话修改地址可能断线，建议使用机器人本机终端或已有独立恢复通道。软件显示的事务编号用于重连后确认或撤销。

### 2. 验证地址与共享联网

保持向导等待确认，在机器人另一终端运行：

```bash
ip -4 address
ip -4 route get 192.168.1.20
ping -c 3 192.168.1.20
ip -4 route get 1.1.1.1
getent hosts example.com
curl -q --proxy '' --noproxy '*' -I --max-time 10 https://example.com
```

确认有线接口具有 `192.168.1.30/24`，到 `.20` 的路径走该有线接口，需要通过主机联网时到公网的路径也经由 `.20`，并能解析域名、完成 HTTPS 请求。最后一个命令显式关闭应用代理，验证的是主机的共享路由。

主机可反向测试 `ping -c 3 192.168.1.30`。日常使用 SSH 或机器人控制程序时，再验证对应连接；ICMP 被现有策略禁用时，结合这些实际连接判断本地通信。

### 3. 保存连接

验证通过后，回到机器人向导输入 `KEEP`。主机如果仍在试运行，也要在主机向导单独输入 `KEEP`。

保存后运行 `./network_setup.sh --status`，核对连接名称为 `机器人控制网络`、有线地址为 `192.168.1.30/24`。原用户连接保留；同机有非本工具的同名连接时，软件要求重新命名，先核对用途再选择新名称。

## 完成结果

机器人使用固定 `.30` 接入主机，默认网关和 DNS 为 `.20`。下一步可按[第三篇教程](03_客户端借用主机10808代理.md)配置应用代理。

如果只需要本地控制，可在客户端向导改选 **4. 固定 IP，仅本地管理**，仍填写相同名称和主从地址；此模式不保存默认网关或 DNS。同网段的 `.20:10808` 代理仍可访问。其他联网策略见[从机接入](../03_从机接入.md)。
