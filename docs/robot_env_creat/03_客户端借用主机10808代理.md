# 客户端借用主机的 10808 代理

## 任务

让机器人通过 `192.168.1.20:10808` 使用主机 VPN／代理软件提供的应用代理出口，供 APT、Git HTTPS、curl 等联网。机器人有线地址沿用 `192.168.1.30/24`。

本任务使用主机已有的 HTTP 或 SOCKS5 代理服务。仅开启主机系统 VPN、但没有提供 10808 代理服务时，客户端不能按本教程接入。NetPilot 配置应用代理开关，不将客户端全部流量接入 VPN；Git SSH、ICMP 和系统服务需要各自可用的网络路径。

## 通过软件执行

### 1. 在主机准备代理服务

先完成前两篇教程，确认机器人能够访问 `192.168.1.20`。在主机的 VPN／代理软件中检查：

| 设置 | 本教程使用的值 |
|---|---|
| 代理监听地址 | `192.168.1.20`，允许机器人访问 |
| 代理端口 | `10808` |
| 代理协议 | 以该端口实际提供的 HTTP、SOCKS5 或混合协议为准 |
| 访问范围 | 只放行需要的客户端，本例为 `192.168.1.30` |

代理软件可能把局域网访问选项叫作“允许局域网连接”或“Allow LAN”。如果只能监听 `0.0.0.0`，按主机已有访问策略限制客户端范围。只监听 `127.0.0.1` 的端口无法供机器人访问。10808 应是代理入口，不是管理或控制 API 端口。

可在主机终端查看 TCP 监听地址：

```bash
ss -lnt 'sport = :10808'
```

NetPilot 不修改主机代理软件或防火墙。监听地址和访问策略需要在现有软件中完成。

### 2. 在机器人配置 NetPilot

在机器人的项目目录运行：

```bash
./network_setup.sh proxy
```

这相当于主菜单 **7. 应用代理**。选择 **1. 配置/更新**，按下表填写：

| 软件提示 | 选择或输入 |
|---|---|
| 代理协议 | 10808 提供 HTTP 时选 **1. HTTP/HTTP CONNECT**；提供 SOCKS5 时选 **2. SOCKS5，域名由代理端解析** |
| 主机代理监听地址 | `192.168.1.20` |
| 代理端口 | `10808` |
| 认证用户名 | 无认证时回车；有认证时填实际用户名 |
| 认证密码 | 有认证时在不回显提示中输入 |
| 不走代理的主机列表 | `localhost,127.0.0.1,::1,192.168.1.20,192.168.1.30` |

端口号不能判断协议。混合端口可选择它支持的 HTTP 或 SOCKS5；不要因为访问 HTTPS 网站就选择“使用 TLS 连接代理服务器”。软件中的 SOCKS5 使用 `socks5h`，目标域名由代理端解析。

确认保存时，软件先备份并清理旧 APT／当前用户全局 Git 代理项，再保存配置和终端开关函数。需要保留现有配置时，先核对提示的备份与清理范围；其他 Git 身份信息保留。

对“现在从本机通过此代理测试 HTTPS”选择 `y`，或者在代理菜单选择 **2. 测试当前代理**。测试通过后退出工具；此时保存了配置，但父终端尚未启用代理。

### 3. 在机器人 Bash 终端启用

使用运行 NetPilot 的同一普通用户，在 Bash 终端执行。使用 zsh 等其他 shell 时，先运行 `bash` 进入 Bash：

```bash
source ~/.bashrc
netpilot_proxy_on
```

开关会先通过 sudo 写入并验证系统 APT 代理，再设置当前终端的代理环境变量；如果提示失败，先按软件提示处理，不继续下面的联网操作。

在该终端按所需应用验证：

```bash
curl -q -I --max-time 15 https://example.com
git ls-remote https://github.com/git/git.git HEAD
sudo apt update
```

Git 示例使用 HTTPS 地址。系统 APT 代理会影响这台机器的 APT；Git HTTPS、curl 等使用当前终端环境，新终端需单独运行 `netpilot_proxy_on`。公网 ping 不经过应用代理，不能用它验证本任务。

### 4. 用完关闭

在启用代理的同一 Bash 终端执行：

```bash
netpilot_proxy_off
```

软件先撤销并验证本工具的 APT 配置，再恢复该终端启用前的变量。关闭应用代理不撤销机器人固定 IP 或共享路由。

## 完成结果

机器人所需应用可通过主机的 10808 代理联网，`.20` 与 `.30` 的本地控制通信保持直接访问。连接被拒绝时先检查主机监听地址、端口和访问策略；协议错误时核对 10808 的实际配置。更多步骤见[应用代理](../06_应用代理.md)和[诊断与故障处理](../07_诊断与故障处理.md)。
