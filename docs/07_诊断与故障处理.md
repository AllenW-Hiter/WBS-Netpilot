# 诊断与故障处理

## 查看状态和导出

```bash
./network_setup.sh --status
./network_setup.sh --diagnose
./network_setup.sh --diagnose --online
```

状态显示物理和虚拟网卡、活动连接、IPv4 与出口采样。诊断保存 JSON 至 `~/netpilot-exports/`；`--online` 才额外测试 HTTPS。报告不包含完整认证秘密，仍可能包含 IP、SSID、连接名称等，分享前检查。

## 分别验证三种路径

1. 本地管理：检查从机能否访问主机下行地址和 SSH。
2. 共享路由：检查从机默认路由、DNS，再显式关闭应用代理测试 HTTPS。
3. 应用代理：通过代理菜单测试，再开启终端函数验证所需应用。

```bash
ip -4 address
ip -4 route
ip -4 route get 1.1.1.1
getent hosts example.com
curl -q --proxy '' --noproxy '*' -I --max-time 10 https://example.com
```

不要把主机连接激活或公网 ping 成功当作从机共享成功。HTTP 代理测试成功也不证明 ICMP 或整机流量可达。`ping` 接受主机名/IP，不能使用 `https://...` URL。

## 常见问题

| 现象 | 排查方向 |
|---|---|
| 找不到可选网卡 | 查看 `--status`；确认物理接口由 NetworkManager 管理，不自动接管 unmanaged 接口 |
| 上行尚未连接 | 先完成[本机上行](04_本机上行.md) |
| 网段重叠 | 检查其他接口、Docker 网桥、VPN 和路由，重新填写双方网段 |
| 固定从机地址与 DHCP 冲突 | 使用排除固定地址的自定义池，或专用单静态链路；自动池不提供保留租约 |
| 主机可以上网、从机不行 | 检查地址、网关、DNS、主机转发与 Docker/UFW/nftables/VPN 策略 |
| APT 仍连接旧代理端口 | 检查完整文件名顺序、主配置、按主机和 binary 规则；使用代理菜单清理旧项 |
| 恢复菜单没有备份选项 | 菜单只读取单连接 JSON；系统 `.tar.gz` 不是该入口的恢复文件 |

APT 配置定位：

```bash
sudo apt-config dump | grep -iE 'proxy|Dir::Etc'
sudo grep -RnsEi 'proxy' /etc/apt
```

Git 配置定位时只看来源和键名，避免输出代理认证：

```bash
git config --show-origin --name-only --get-regexp '^(http(\..*)?\.proxy|remote\..*\.proxy|core\.gitproxy)$'
```

## 事务异常

`confirmed-not-saved` 表示检查点已确认但磁盘保存未完成；应检查当前连接，通过已有连接或备份恢复。此时不能假设原检查点还能回滚。`rollback-needs-attention` 表示无法确认恢复成功，应在本机检查。

不清空防火墙、不删除 Docker 网桥、不重启所有网络服务来掩盖故障。先保留状态和恢复通道，再逐项处理。恢复方法见[备份教程](08_连接管理与备份恢复.md)。
