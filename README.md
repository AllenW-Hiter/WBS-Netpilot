# NetPilot：主／从电脑交互式网络配置工具

**版本：0.1.0｜状态：可试用的首版，已通过离线测试，尚未完成 Ubuntu/CM5 实机验收。**

同一份程序分别在主电脑和从电脑上运行。Bash 入口检查并按需安装发行版软件包，Python 负责向导、校验和记录，NetworkManager 负责连接、热点及 IPv4 共享。

目标环境是 **Ubuntu 22.04/24.04、使用 NetworkManager 的 Ubuntu/Debian 系统，以及满足这些条件的 Radxa OS**。使用系统 `/usr/bin/python3`；不要用 Conda/虚拟环境替换，因为 `python3-dbus` 来自系统软件包。其他版本和无线驱动需要实测，不能仅凭安装成功认定兼容。

本工具不修改设备树、USB 模式、系统休眠设置，不依赖 `rsetup`。它不是完整软路由，也不是任意 VPN 软件的透明共享器。

## 1. 开始使用

请解压整个项目，不要只复制 `.sh` 文件。它需要同目录中的 `netpilot.py` 和 `netpilot_lib/`。

```bash
cd netpilot
chmod +x network_setup.sh

# 第一步：只读检查，不安装软件、不改网络
./network_setup.sh --check

# 第二步：不依赖 NetworkManager 的离线示例
./network_setup.sh --demo

# 第三步：启动交互向导。需要写系统配置时使用 sudo 权限
./network_setup.sh
```

也可以直接进入角色向导：

```bash
./network_setup.sh host
./network_setup.sh client
./network_setup.sh uplink
```

缺少基础依赖时，启动器会列出缺失软件包，询问是否通过系统 APT 软件源安装。热点、无线和诊断依赖在进入相关功能时进一步检查。不会下载远程脚本执行，不使用 pip，不运行全系统 upgrade/full-upgrade。

**安装依赖需要已经可用的上行。** 如果 Wi-Fi 关闭且有线只是连接 CM5，就可能没有下载通道；请先恢复一个可用网络。完全离线时，本版会停止并提示缺少的包，不会假装自动解决引导依赖。安装 NetworkManager 软件包可能启动该服务，不应在没有恢复通道的 SSH 会话中盲目安装。程序不会自动修改 Netplan 的 renderer 或接管 unmanaged 网卡。

## 2. 已实现的范围

| 功能 | 本版行为 |
|---|---|
| 网卡识别 | 区分有线、无线、系统/虚拟接口；读取无线 phy；默认排除 `lo`、Docker 网桥、P2P 和未托管设备 |
| 主机共享 | 有线→热点、无线→有线、两张独立物理无线网卡之间共享、有线→有线 |
| 主从地址 | 手动输入网段及主从机末段 `.X`，检查地址合法性、重复地址和网段冲突；主机计划保留从机地址建议 |
| 有线连接命名 | 创建主机、从机或上行有线连接时手动输入名称；与非本工具配置重名时由用户重新命名 |
| 本地管理 | 有线固定地址、不启用共享；能停止本工具的有线共享而保留管理地址 |
| 从机 | DHCP、固定 IP 持久网关、固定 IP 按需网关、仅本地管理 |
| 上行连接 | 新建 DHCP/静态有线连接，或 WPA2/WPA3 Personal Wi-Fi；企业认证可激活系统已有连接 |
| 配置清理 | 按 UUID 查看、备份、激活、断开、修改自动连接；经确认批量删除非活动普通配置 |
| 代理 | HTTP/HTTPS/SOCKS5h 应用代理；两个 Bash 函数统一开关 APT 和终端应用代理；旧 APT / 用户 Git 代理项备份清理；单命令代理 |
| 安全 | 计划预览、子网重叠检查、可选有线 ARP 探测、原配置备份、试运行检查点、临时路由独立回滚 |
| 迁移与诊断 | 不含密码的 JSON 计划与 Markdown 配置卡、导入时重新选网卡、本机诊断报告 |

**主机共享的出口跟随系统路由。** 选择上行网卡用于角色检查和展示，不意味着为下游流量建立了独立的出口绑定。多默认路由、VPN、策略路由会影响实际出口；应在主机和从机分别验证。

以下功能尚未实现：下游独立出口策略、任意 VPN 透明网关、VPN 强制断线保护、单 phy 同时 STA+AP、IPv6 共享、DHCP 静态租约管理、自动改写 Netplan YAML、自动修改 Docker/UFW/nftables 转发规则、离线依赖包下载器、远程批量部署。详见修订计划。

```text
3. 配置从机／客户端
4. 配置本机上行
5. 管理已有连接
6. 临时联网路由
7. 应用代理
8. 停止有线共享但保留管理地址
9. 备份／恢复

11. 诊断与导出报告

```

新建热点明确使用 WPA2/RSN + CCMP，或用户选择 WPA3/SAE；失败时不降级到 WEP/开放热点。双无线场景要求两个不同的 `phy`。硬件、驱动和监管域不支持时会失败，而不是编造成功结果。

## 4. CM5 的推荐使用顺序

先保持本机终端或串口可用。主机和 CM5 最初可能不在目标网段；切换两端地址必然可能暂时断开 SSH。

### 主电脑

运行 `./network_setup.sh host`，选择“Wi-Fi 上行 → 有线共享（控制robot常用）”。选择真正上网的 Wi-Fi，以及面向 CM5 的以太网接口。你先前的输出中它们分别是 `wlp0s20f3` 和 `enp89s0`，但每次仍以当前检测为准。

选择有线下行接口后，先输入连接名称，再输入网段、主机地址末段和从机地址末段，不再选择教程或通用地址预设。例如：

```text
请输入连接名称：robot主机共享
请输入网段：192.168.1.0/24
主机地址末段 .X：20
从机地址末段 .X：40
结果：主机 192.168.1.20/24，从机 192.168.1.40/24
```

网段也可简写成 `192.168.1` 或 `192.168.1.`，表示 `/24`；末段可写 `20` 或 `.20`。支持 `/8～/30`，较大网段可输入完整 IPv4 地址来指定不同的第三段。输入没有地址默认值，必须自行填写。主机配置只应用本机地址，从机地址作为建议保存到计划和配置卡，仍需在从机配置。如果上游 Wi-Fi 已使用该网段，脚本会要求重新输入，两端应采用相同的新网段。

### CM5／从电脑

运行 `./network_setup.sh client`，选择实际接口，例如 `end1`。选择“固定 IP，按需临时网关”，再输入与主机一致的网段和主从机末段。沿用上面的输入可得到：

```text
地址：192.168.1.40/24
持久默认网关：无
按需网关建议：192.168.1.20
DNS：默认建议主机 192.168.1.20
IPv6：只在这份新连接中禁用
```

主机、从机和上行的有线新连接都由用户输入名称，没有默认名称；支持 1～100 个可打印字符，包括中文和内部空格。与非本工具创建的配置重名时，保留原配置并等待用户输入其他名称，不自动添加后缀。试运行期间临时显示为“用户名称 [试运行]”，输入完整大写 `KEEP` 确认并保存后使用用户填写的最终名称。程序按 UUID 管理连接。

**不要混用旧教程的函数与新工具。** 旧 `radxa_internet_on/off` 可能严格检查连接名，且旧路由没有本工具标记。迁移前先结束旧函数创建的临时路由，以后用本工具管理。新工具不会自动接管或删除无法确认归属的旧默认路由。

### 按需联网

主机共享正常后，在从机运行：

```bash
./network_setup.sh route-on
# 选择网卡、主机地址和 metric；测试后输入 KEEP

./network_setup.sh route-off
# 只撤销本工具登记、仍存在的临时路由
```

临时路由带 `proto 242` 和精确的接口/网关/metric 记录，使用 `add` 而不是覆盖其他默认路由的 `replace`。重启或 NetworkManager 重建连接后它可能消失；程序会清理失效的记录。`route-off` 不是断开所有互联网访问的总开关，不关闭应用代理和其他接口。

### 固定 IP 与 DHCP 的版本限制

支持 `ipv4.shared-dhcp-range` 时，向导可设置动态地址池，并拒绝包含已填写的主机或从机固定地址的范围。`/24` 网段仅在 `.100～.199` 不覆盖这些地址时提供该范围作为输入建议。地址仍需统一管理，不能把另一台静态设备设成相同地址。

NetworkManager 不支持该字段，或用户选择使用自动地址池时，不能宣称输入的从机地址已自动保留。向导要求明确选择：下游全部 DHCP（实际地址由 DHCP 分配），或专用直连、仅一台静态从机且不混接 DHCP 客户端。需要“多台静态设备 + DHCP 动态设备”的部署，应先解决地址池/租约管理能力，再正式使用。

## 5. 安全试运行与 SSH 恢复

网络连接切换前会备份并创建 NetworkManager 检查点。新连接先以 **内存配置、禁止自动连接** 试运行，原始配置保持不变。默认 180 秒内输入 `KEEP` 才提交。可以提前设置更长的检查时限：

```bash
./network_setup.sh --timeout 300 host
```

在激活前，终端会显示一个事务编号，例如 `a1b2c3d4e5f6`。SSH 中断时，可以重新连接到新地址，并在相同项目目录执行：

```bash
./network_setup.sh confirm a1b2c3d4e5f6
# 或主动撤销：
./network_setup.sh rollback a1b2c3d4e5f6
```

不确认时，由 NetworkManager 自己执行超时回滚，不依赖原 SSH 终端继续运行。临时 `ip route` 操作不假借 NetworkManager 检查点保护，而使用独立的 systemd 定时恢复任务；没有可用 systemd 环境就拒绝执行这类路由变更。

提交检查点之后才持久化新配置。极端情况下，如果确认后磁盘写入失败，状态会记录为 `confirmed-not-saved`，原持久配置仍保留；这不是“保存成功”，需要检查并重新激活旧连接或从备份恢复。断电、网卡拔出、驱动崩溃、外部管理员同时改网等情况不能靠脚本保证完全恢复。

全局“开启 Wi-Fi 射频”以及安装软件包不是设备连接检查点的一部分，均单独提示风险并要求确认。不会提供静默关闭所有 Wi-Fi 的快捷操作。

## 6. 从机使用主机代理端口

主机的代理程序必须已配置好监听地址、端口和访问限制。这里填的是 HTTP/SOCKS 代理端口，不是代理软件的控制 API 端口，也不是随意填写一个“VPN 端口”。不要将无认证代理向不可信网络开放。

```bash
./network_setup.sh proxy
```

菜单不再提供独立的“启用/关闭 APT 覆盖项”：

```text
1. 配置/更新
2. 测试当前代理
3. 安装/更新终端代理开关函数
4. 清理旧 APT / Git 代理配置
5. 移除本用户代理配置
0. 返回
```

选择“配置/更新”，填写协议、主机地址、端口和可选认证信息。确认保存后，先私有备份并清理旧 APT 代理项和当前用户 Git 的代理项，再在 `~/.bashrc` 写入两个函数。认证信息保存在 `~/.config/netpilot/` 的 `0600` 文件中，不写入 `.bashrc`。当前父终端不会被子进程直接修改；退出工具后执行：

```bash
source ~/.bashrc
netpilot_proxy_on
# 验证 APT / Git HTTPS / curl
sudo apt update
git ls-remote https://github.com/git/git.git HEAD
curl -I https://example.com
netpilot_proxy_off
```

开启函数先通过 sudo 写入并检查 APT 生效配置，再设置本终端的代理环境变量；失败时不修改终端变量。关闭函数先关闭 APT 并验证，再恢复本终端启用前的变量。新终端只定义函数，不自动设置终端代理；APT 保持系统当前开关状态。APT 开关影响系统 APT；Git HTTPS、curl 等环境变量影响当前终端及以后从该终端启动的程序。Git SSH、其他终端、已启动进程和不支持代理变量的程序需分别处理。Git 仓库级或系统级代理配置也可能覆盖环境变量。

已有配置只需升级函数时，先选菜单 4 清理旧代理项，再选菜单 3 安装/更新函数。也可以显式清理：

```bash
sudo ./network_setup.sh proxy-cleanup
```

清理读取 `/etc/apt/apt.conf` 和生效的 `apt.conf.d` 文件，删除完整单行代理指令，保留其他设置；只含代理指令和注释的文件会移除，包括旧 `99proxy` 和 `99-netpilot-proxy`。嵌套/无法确定范围的代理语法、符号链接会停止，需人工整理。Git 清理范围为当前用户全局配置及其主目录内的 include 文件，保留姓名、邮箱和其他设置；不遍历所有仓库或改系统 Git 配置。APT 备份在 `/var/lib/netpilot/backups/proxy/`，Git 备份在 `~/.config/netpilot/legacy-proxy-*`。历史备份和其他软件的代理设置不会被清除。

单个命令使用代理，不修改父终端：

```bash
./network_setup.sh proxy-run -- curl -I https://example.com
```

函数内部通过 `/etc/apt/apt.conf.d/99-netpilot-proxy` 实现 APT 开关，文件仅 root 可读，关闭后移除。HTTP、HTTPS、SOCKS5h 协议原样写入，不猜测转换。开启/关闭均检查 `apt-config dump`；发现旧文件、按主机规则、自动检测或 binary 专用规则冲突时恢复原文件并返回失败。实际请求是否可达仍需上面的 APT/Git/curl 命令验证。`proxy-run` 仅设置单命令的环境，不操作系统 APT 开关。

**同网段从机没有互联网默认路由，也可能通过主机的应用代理访问互联网。** 因此移除临时默认路由不等于关闭代理。要实现严格阻止访问/必须 VPN，需要独立的防火墙和出口策略，本版没有实现。

## 7. 预览、导出与测试

全局参数放在子命令前。错误位置的参数会被拒绝，而不是被忽略后执行真实变更。

```bash
# 对计划文件做纯参数检查，不接触系统网络工具
./network_setup.sh --dry-run --plan examples/cm5_client.json

# 使用本机发现的接口完成只读交互预览
./network_setup.sh --dry-run host

# 只读状态/诊断；诊断会保存一个本用户报告
./network_setup.sh --status
./network_setup.sh --diagnose
./network_setup.sh --diagnose --online

# 运行离线单元测试，无需 NetworkManager 服务
./network_setup.sh --self-test
```

成功配置后可以导出 JSON 计划和 Markdown 配置卡到 `~/netpilot-exports/`。文件不包含 Wi-Fi 密码或代理密码；它们仍含 IP、SSID 等信息，分享前请检查。导入计划会重新选择本机网卡，Wi-Fi 密码在实际应用时单独输入。

`--dry-run --plan` 仅进行静态校验，不能证明现场接口存在、没有 IP 占用或热点一定兼容。

当前共 183 项离线单元/模拟测试通过，包含 28 项自定义主从地址输入测试、11 项连接命名测试和 36 项统一代理开关测试；记录见测试报告，未完成真实联网验收。

## 8. 文件与隐私

| 位置 | 内容 |
|---|---|
| `/var/lib/netpilot/managed.json` | 本工具创建的配置 UUID 和角色 |
| `/var/lib/netpilot/pending/` | 连接事务和状态，不包含 Wi-Fi 密码 |
| `/var/lib/netpilot/backups/profiles/` | 可恢复连接备份，可能含密码，仅 root 可读 |
| `/var/lib/netpilot/backups/system/` | NetworkManager/Netplan 源文件归档，可能含密码 |
| `/var/lib/netpilot/backups/proxy/` | 清理前的 APT 配置备份，可能含代理认证信息，仅 root 可读 |
| `/var/lib/netpilot/routes.json`、`route-actions/` | 本工具临时路由的归属和恢复记录 |
| `/var/lib/netpilot/audit.jsonl` | 精简操作日志，不记录完整敏感命令 |
| `~/.config/netpilot/` | 本用户代理配置、Shell 函数及旧配置备份，可能含认证信息 |
| `~/netpilot-exports/` | 无密码计划、配置卡与诊断报告 |

私有权限不等于加密。不要把以上运行时目录或备份提交到 GitHub。
